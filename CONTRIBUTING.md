# Contributing

Standards contributions and hosted-catalog contributions have different workflows.

## Specifications and code

Open an issue with the problem, a concrete example, and the affected field or workflow. Avoid posting private resident details, credentials, restricted locations, or material you do not have permission to share.

For a change, submit a pull request that explains:

1. The use case and who needs it.
2. The proposed schema or interpretation change.
3. Its effect on existing records and publishers.
4. Valid and invalid examples and the validation result (`npm test`).

Use unknown/null values when evidence is missing. Do not infer an event mechanism from a photograph or imply that a listed service has confirmed capacity.

Small clarifications are welcome. Larger changes should begin with an issue so affected partners can discuss them before implementation. Current maintenance is led by Floodline; the collaborative governance model is still developing.

## Data in the Floodline catalog

Contact the founding steward at gibsontchu@gmail.com to discuss a partnership or contribution. Approved contributors propose drafts; editors decide publication. Contributing a record does not itself clear the rights to its attachments.

Independent implementations are welcome and do not require permission to use the specification. Please identify the exact schema version you implement and distinguish schema validation from editorial or factual verification.
